# AI 提供商 (Providers) 与模型配置指南

进入“设置” -> “AI 提供商”，可添加或修改大模型 API 配置。列表页每行与 MCP 列表同款：左侧品牌 logo（**按提供商名称自动识别**，如名为 DeepSeek 即显示 DeepSeek 图标，识别不到时回退按协议类型显示），第一行提供商名称，第二行协议类型（OpenAI / Anthropic / Gemini）与模型数量 tag，右侧启用/停用状态 tag + 箭头，行尾为拖拽手柄（≡）。点击行进入编辑页，**左滑该行**露出红色「删除」按钮可删除提供商；**长按行尾拖拽手柄上下拖动可调整提供商顺序**（重启后顺序保持不变）。

提供商编辑页底部悬浮胶囊 tab 栏分两个标签页：**配置** 与 **模型**。

## 1. 配置 Tab 字段
*   **名称**：文本框。给提供商取个别名（如“我的中转 API”）。留空保存时自动填“新提供商”。
*   **类型**：FilterChip 三选一：`OpenAI` / `Anthropic` / `Gemini`。决定发包协议。第三方中转站基本都选 `OpenAI`。
*   **API Key**：文本框。填入秘钥（如 `sk-xxx`）。
*   **输入自动清洗**：保存（含返回自动保存）与「拉取模型」时会自动清理配置里的多余空白：**API Key / Base URL / 代理主机去掉全部空白字符**（含中间的空格与粘贴带入的换行），名称 / 模型名 / User-Agent / 面板脚本路径 / 代理账号密码去掉换行与制表符并裁掉首尾空格。粘贴秘钥时尾部带换行曾会导致请求头非法而报 `Unexpected char 0x0a in Authorization value`，现在旧配置在读取时也会一并清洗，无需手动重填。
*   **Base URL**：文本框。填 API 根域名，placeholder 随类型变化（OpenAI→`https://api.openai.com/`，Anthropic→`https://api.anthropic.com/`，Gemini→`https://generativelanguage.googleapis.com/`）。留空时按类型回填默认值。不要带尾部的 `/v1` 或具体的 path。
*   **API 地址**：文本框。紧跟 Base URL 后的请求路径，默认 `/chat/completions`。
*   **Response API (新版)**：开关，仅当类型为 `OpenAI` 时显示。默认**关闭**。开启后该提供商的所有对话改走 OpenAI Responses 协议：端点自动换成 `/v1/responses`，请求体用 `input` item 序列（工具调用与结果是独立的 `function_call` / `function_call_output` item），流式按语义事件解析并以 `response.completed` / `response.incomplete` / `response.failed` 结束（Responses 不发 `[DONE]`）。文本流、思考过程、工具调用、图片输入、token 用量与超长自动续写均已支持，「模型」Tab 的连通性测试也会改用该端点。**仅在服务端确实支持 Responses 时开启**（如 OpenAI 官方、`https://api.deepseek.com`），不支持的中转会直接报 400；同时开启「完整 URL」时，填的地址必须指向 responses 端点，不能仍指向 `/chat/completions`。
*   **User-Agent**：文本框。自定义该提供商所有 AI 请求（对话/流式/识图）的 `User-Agent` 请求头，留空使用默认。部分中转网关会校验 UA，可按需填写（如 `MyApp/1.0`）。
*   **自定义面板脚本**：文本框与选择器。配置执行当前提供商自定义面板/余量统计的脚本文件（存放于 `~/.aicode/scripts/`，如 `demo_balance.py` 或 `demo_subscription.py`），支持 Python/Bash/Node 等。配置后可在编辑页点击「运行测试」实时调试输出；在主聊天界面输入框上方会自动展示该提供商的自定义面板卡片（支持折叠/展开视图）。脚本执行时会自动注入当前模型、工作区、会话 ID 及每次请求的 Token 统计等环境变量，每次 Agent 单次 LLM 请求完成时会自动刷新面板。如需深度自定义排版与卡片布局，可参考 [自定义面板 (DIY Dashboard) 与 Adaptive Cards 设计规范指南](provider-dashboard-cards-guide.md)。

## 2. 模型 Tab
*   **拉取模型**：点击“拉取模型”按钮，向提供商同步可用模型列表；结果按品牌分组、可折叠，支持名称搜索筛选，每个模型旁标注元数据标签（`Image`(支持图片) / `Tools`(支持工具调用) / `↑<上下文>`(输入) / `↓<最大输出>`(输出)）。
*   **手动添加模型**：点击右上角 + 或“添加模型”，输入模型名（如 `gpt-4o`）即可加入；编辑弹窗还可自定义该模型的元数据：**上下文窗口**（影响上下文压缩触发阈值）、**输出窗口**（该模型单次回复的最大输出 token；Anthropic 协议会按此值发 `max_tokens`，未填写时回退自动解析值、都取不到时用 16384 兜底）、**价格**（输入 / 输出 / 缓存命中，单位 USD/1M tokens，键盘为数字输入）与 **能力开关**（图片输入、图片输出、工具调用、推理能力）。自定义值优先级高于自动解析（拉取/内置）：窗口/价格未填写时回退到自动解析值（价格三级回退：自定义 > 拉取 > 内置），能力开关默认跟随自动解析结果。自定义元数据会应用到对话识图判断、上下文压缩与识图模型列表的能力标注。重复添加会被拦截提示。
*   **元数据自动解析兜底**：自动解析（拉取/内置）匹配不到模型时，会尝试去掉常见后缀（`-thinking` / `-preview` / `-high` / `-low` 及 `(thinking)` / `(xhigh)` / `(high)` / `(low)`，可连续剥多层）后再匹配一次；自定义元数据始终按输入的模型名精确匹配。
*   **思考强度（推理档位）**：输入框的思考强度按钮（⚡）**始终显示**。当前模型能在元数据（models.dev 的 `reasoning_options` 中 effort 档位）里匹配到档位时，只列出该模型支持的子集（如 o 系列仅低/中/高、gpt-5-pro 仅高）；**匹配不到时（模型无 effort 档位，或中转站改过模型名导致元数据未命中）列出全部档位** `关闭` / `极低` / `低` / `中` / `高` / `极高` / `最高`，由你自行选择——部分中转模型强制开启推理但名称非标准，这样仍可手动调档。选择会同步记忆为该模型的默认档位，新建会话绑定该模型时自动沿用。
*   **测试**：每个已添加模型行有“测试”按钮，对该模型发起一次连通性请求，行下方显示成功/失败结果。
*   **删除**：模型行左滑露出「删除」按钮可移除该模型。保存后若被移除的模型正被选用，相应选中会自动清除并回退——包括该提供商的生效模型（`selectedModel`）、「默认模型」页的新会话默认模型，以及识图 / 上下文压缩 / 标题总结模型；已绑定该模型的历史会话在下次使用时也会回退到默认模型，不会再用已删除的模型发起请求。
*   **生效模型**：实际出战模型取 `selectedModel`，为空时回退到 `defaultModel`（即 `effectiveModel`）。启用/停用某个提供商在编辑页「选项」分组中切换。
*   **模型中止回答时的提示**：Anthropic 协议下，若服务端因内容安全策略拒答（`refusal`）或本次输入超出模型上下文窗口（`model_context_window_exceeded`），回复可能为空。这种情况不再静默结束成空白气泡，而是展示失败提示（如「模型基于内容安全策略拒绝了本次回答」「本次输入超出模型上下文窗口，请先压缩上下文或新建会话」），服务端附带具体理由时一并显示。

## 3. 识图模型
进入「设置」->「默认模型」-> 点击「识图模型」，可为识图（`viewImage` 工具）指定使用的模型：

*   **跟随当前聊天模型**（默认，列表首项）：识图会话使用当前选中的聊天模型。
*   **指定专用模型**：选择某个提供商下的模型，识图会话固定使用该模型（不随聊天模型切换）。

识图工具（`viewImage`）行为：
*   首次传 `images`（1~5 张图片路径）让识图模型一次性分析/对比，返回 `vision_id` 与文本结果；之后传 `vision_id` + `prompt` 在同一识图会话内继续追问，识图模型记得图片与之前的问答。
*   `detail` 参数控制图片细节：`high`（默认）小图原样直传、大图（>4MB）压缩到最长边 1536；`original` 全部原样直传（多张大图可能超出模型限制导致失败）；`low` 全部压缩到最长边 512 省 token。
*   会话请求体（图片与问答历史）落盘在 `~/.aicode/vision-sessions/`，App 重启后已返回的 `vision_id` 仍可继续追问。
*   **不校验模型的图片输入能力**：选到不支持图片的模型时，识图调用会失败，错误信息会原样作为工具结果返回给 AI，由 AI 自行处理（如提示用户更换模型）。
*   列表中每个模型旁标注是否「支持图片输入」（依据模型元数据 `supportsVision`），供选择时参考，但不会拦截保存或调用。

## 4. 标题总结专用模型
进入「设置」->「默认模型」-> 点击「标题总结模型」，可为新建会话的标题生成单独指定一个模型：

*   **跟随当前聊天模型**（默认）：标题生成用当前选中的聊天模型。
*   **指定专用模型**：选择某个提供商下的模型。新建会话发送首条消息后，会用该专用模型**异步**生成会话标题，成功后替换本地截断的临时标题。

要点：
*   标题生成在首条消息发送后**后台异步**执行，不阻塞对话；生成失败或取不到标题时保留本地截断的临时标题。
*   标题生成提示词内置在 `prompts/agent/title-generator.md`，可在 `~/.aicode/prompts.custom/agent/title-generator.md` 覆盖。
