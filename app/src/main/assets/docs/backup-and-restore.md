# 备份与还原 (Backup)

进入「设置」->「备份与还原」，加密导出/导入应用配置、聊天历史、凭据与工作区文件。

## 1. 导出备份
*   **选择导出数据**：页面上方「选择导出数据」分组内勾选要导出的数据范围（AI 提供商、Git 凭据、连接与同步、聊天历史、MCP 服务器、授权规则、应用设置、工作区文件）。勾选状态会自动记忆，下次进入页面沿用；其中「工作区文件」默认关闭，需要时手动开启。
*   **工作区文件**：打包所有**本地模式的内部工作区**文件（含 `.git` 目录，可完整还原仓库历史与未推送的提交）。外部本地目录工作区属于用户设备上的原始目录，不会被递归打包。排除规则 = 各工作区自己的 `.gitignore`（按根目录锚定匹配）+ 同步功能的忽略清单（`node_modules`、`build`、`dist` 等默认目录），符号链接不备份。该开关下方带提示：**工作区文件建议通过 Git 提交备份，导出备份仅作备用**（Git 仓库本身已完整保存代码与历史，此处的导出适合作为额外备份手段）。
*   **设置导出口令**：点击「导出备份」后弹窗设置口令，留空则输出明文 tar.gz；填写则用口令加密（AES-GCM）。
*   导出格式为 tar.gz 压缩包，含 API Key 等凭据，通过系统文件选择器保存到指定位置。

## 2. 导入备份
*   从备份文件还原数据，合并方式导入，不清除现有数据。
*   需输入对应口令；备份未加密则留空。
*   **工作区文件**：备份含内部工作区数据时，会先弹出「恢复工作区」选择弹窗，列出备份中的每个工作区（名称 + 文件数），可勾选要恢复哪些；弹窗内有**覆盖警告**——将直接覆盖本地同名工作区中的文件且无法撤销。确认后只恢复勾选的工作区；本地不存在同名工作区时会自动新建同名工作区再写入文件，避免新设备/重装后数据丢失。远程模式工作区（文件在服务器上）不参与还原。
*   导入完成后展示已还原数据汇总（提供商、Git 凭据、远程连接、远程挂载、聊天会话、聊天消息、待办项、MCP 服务器、全局授权规则、工作区文件等数量）。

## 3. 注意事项
*   口令丢失则加密备份无法恢复。
*   导入后应用内仍按现状明文存储。
