# 日志查看、私有目录挂载与后台运行保活

## 1. 访问容器私有目录 (~/.aicode 等)
Android 沙盒限制了普通 App 访问深层目录，但用户可以通过以下方式无缝访问和管理深层配置：
1.  **使用文件管理器挂载 (DocumentsProvider)（推荐）**：App 内部暴露了标准的 `DocumentsProvider` 服务。你可以使用手机自带的“文件”管理器或第三方文件管理应用（如 MT管理器、Solid Explorer 等）找到并挂载 App 的私有根目录。
    *   **挂载后可见的核心目录**：
        *   `projects/`（工作区项目）：存放你在 App 内创建或导入的所有本地代码项目。外部本地目录工作区（通过工作区面板「添加本地目录」选择）物理上位于你选择的设备目录，不在 `projects/` 下。
        *   `aicode/`（AI 核心配置）：对应容器内的 `~/.aicode` 目录。内含 `skills/`（扩展技能脚本）、`docs/`（系统文档）与 `mcp.json`（MCP 配置），可在此直接管理自定义技能和配置。
2.  **使用内置终端 (Terminal)**：在主界面侧边栏切到 **终端** 页面。可以直接输入 `cd ~/.aicode` 访问配置文件夹，用 `vim` 或 `cat` 查看和编辑 `skills`、`mcp.json` 等内容。
3.  **直接让 AI 操作**：因为 AI 本身就运行在容器内，用户可以直接对 AI 说：“请帮我把 `~/.aicode/mcp.json` 打印出来给我看”，或者“帮我在 `~/.aicode/skills/` 下写一个新的技能文件”，AI 会直接帮你完美完成！
4.  **Root 后直接访问私有目录**：如果设备已获取 Android root 权限，也可以绕过挂载，直接进入 App 宿主私有目录 `/data/data/<包名>/files/`（部分系统等价路径为 `/data/user/0/<包名>/files/`）。其中 `projects/` 是本地工作区根目录，`aicode/` 对应容器内的 `~/.aicode`，`rootfs/` 是容器系统目录。`<包名>` 对应 applicationId：release 为 `com.aicode`，debug（IDE 调试构）为 `com.aicode.debug`——两者私有目录完全隔离，互不可见。

## 2. 查看 App 运行日志 (Log Files)
App 自动将日志落盘到外部存储，同时也提供应用内查看入口：
*   **应用内查看**：进入 **设置 → 日志** 可查看最近日志文件（默认定位今天的日志），页面提供：
    *   **日志等级**：顶部设置行显示当前等级，点击弹出底部面板选择（Verbose/Debug/Info/Warn/Error/None）。
    *   **文件切换**：与日志等级同卡片，点击「日志文件」行从底部弹出日期列表（可滚动），默认选中今天，选中项高亮打勾。
    *   **搜索与复制**：关键字实时过滤日志行，右上角一键复制当前筛选结果。
    *   **彩色分级**：日志按等级着色（Verbose 灰 / Debug 蓝 / Info 绿 / Warn 橙 / Error 红）。
    *   **行复制**：点击任意日志行复制本条完整日志（含时间/等级/来源），长按弹出菜单可自定义复制范围（本条 / 本条及堆栈 / 仅消息内容）。
    *   **实时滚动**：开启后每 3 秒自动刷新日志并跟随最新（默认开启）；关闭后停止刷新、保持手动浏览位置。
*   **MCP 过滤**：进入 **设置 → MCP 服务器** 后，右上角日志按钮可查看全部日志；编辑某个 MCP 时点击日志按钮可按该 MCP 名称过滤（页面顶部显示过滤徽章，可一键清除）。
*   **文件路径**：`/storage/emulated/0/Android/data/<包名>/files/logs/`。无需 Root 权限即可直接用手机文件管理器查看。`<包名>` 随构建变体变化：release 为 `com.aicode`，debug 为 `com.aicode.debug`。
*   **显示限制**：为避免大日志卡顿，应用内日志查看默认显示当前文件在筛选条件下的最后一部分日志；完整文件仍可在上述目录中查看。

### 崩溃错误页 (Crash Page)
应用捕获到未捕获异常时**不会直接闪退**，而是全屏显示崩溃错误页：
*   **错误详情**：页面展示崩溃时的版本、设备、时间与完整堆栈，方便定位问题。
*   **一键复制**：点击「复制错误信息」即可复制完整崩溃报告（含堆栈与日志文件路径），直接粘贴发送给开发者即可，无需手动翻找日志。
*   **重启 / 退出**：页面提供「重启应用」重新进入主界面；按返回键或「退出应用」则完全退出进程。
*   **完整日志**：崩溃日志仍会落盘到上文 `logs/` 目录，可从 **设置 → 日志** 或文件管理器查看。

## 3. 系统配置补充
*   **日志等级 (Log Level)**：控制系统打印日志的详细程度，枚举值为 `Verbose`, `Debug`, `Info`, `Warn`, `Error`, `None`（`None` 用作阈值时关闭一切输出）。遇到 Bug 时建议调成 `Debug`；日常使用保持 `Info`。日志等级与日志查看已合并为一个「日志」二级页；默认等级按构建类型区分：debug 构建为 `Verbose`（开发期全量记录），正式版为 `Info`（过滤调试噪音），用户手动选择后以用户设置为准。
*   **后台运行保活 (Keepalive)**：开启后 Android 系统通知栏会显示常驻服务，防止 AI 在执行超长任务（如编译）切后台时被系统杀掉。
